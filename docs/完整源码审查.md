## 结论与修改

Android 现代 Picker 的注册/启动异常走统一 finish 清理；相机文件使用既有请求 suffix，避免跨实例同毫秒覆盖或删除。保存继续写原字节：Android API28+ 使用 ImageDecoder 拒绝 partial；API24–27 与 Swift/HAR 对 PNG/JPEG/WebP 做结束边界检查后实际解码并释放小尺寸 Bitmap/thumbnail/PixelMap。尺寸元数据或非空 UIImage 不作为完整内容证明。选图 maxCount 公共合同与 Swift/HAR 统一为 1..500，系统可限制更低值。HAR 非字符串保存前缀在解码和原生读写前返回 invalid_content。

## 最低系统与线程

Android：API24+；iOS：iOS14+；OHOS：实际 target/compatible API22。Android registry/权限在 Main，图片与文件工作在既有 IO 边界；iOS UIKit/Photos 桥回执与取消沿 Main 归属，图像处理沿现有执行器；HAR 保持页面 request owner 与异步资源收尾。

## 公开调用链

- ImagePickerRequest → AndroidImagePickerPlatform → registry / FileProvider → IO 采样、EXIF 旋转及输出 → request owner 清理。
- ImageSaveRequest → Android 采样验证 → 旧系统 Main 权限 → MediaStore pending 写入/失败删除。
- IosMediaSdkBridge / KmpMediaBridge → Swift MediaClient / UIKitContext / ImageSelectionProcessor → Photos；delegate、取消和迟交付归属一致。
- Kuikly MediaModule → HAR MediaModule → Picker / camera / 相册资源读写；requestId、busy、总大小限制及原生 finally 清理。

## 保存格式边界与 Swift 真实回归

`bash scripts/verify-ios-picker.sh` 在 booted iOS Simulator 独立编译 Swift 产品/消费应用并运行成功：真实 2×2 PNG 截到 IHDR+IDAT type，原 UIImage、ImageIO thumbnail 与 incremental source 均返回部分图像；修复后生产 saveImage 返回唯一 invalidContent，未触发 Photos 授权。完整 PNG/JPEG 和尾随数据仍有效；缺主图 EOI 且 APP1 内嵌 EOI 的 JPEG（UIImage 仍非 nil）被拒绝。既有 Picker ownership、cancel、UIKit transitions/presenter containers 同次通过。日志为 build/full-review/final-swift-picker.log，原始行为探针为 image-fixture/result.log。KMP IosImageSavePlatform → KmpMediaBridge → MediaClient.saveImage 走同一修复入口。

依据：[ImageDecoder](https://developer.android.com/reference/android/graphics/ImageDecoder) partial listener 返回 false；[W3C PNG](https://www.w3.org/TR/png-3/) 要求最终 IEND；[WebP RIFF](https://developers.google.com/speed/webp/docs/riff_container) 声明大小不能超过实有字节，reader 可忽略尾随数据；[Motion Photo](https://developer.android.com/media/platform/motion-photo-format) 在 JPEG 后附加视频，不能要求 EOI 恰好位于文件末尾。PNG 按 chunk 长度跳到 IEND，JPEG 跳过 APP/metadata 段后查找主 EOI，WebP 核对声明长度；另做小尺寸系统实际解码，保存原字节。

API24–27 BitmapFactory 与 Swift/HAR 兼容边界只保证上述确认截断被拒绝，不构造完整格式解析器，不承诺识别所有压缩数据/CRC 错误或系统容忍的其他部分图像。OHOS 真实 ImageKit/授权仍需设备检查；Node 只验证生产 ETS 控制流，Swift Simulator 不等于真实相册写入验收。
