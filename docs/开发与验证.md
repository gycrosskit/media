## 环境与检查

源码构建使用 JDK 17、Gradle wrapper、Android SDK（compileSdk 36）；iOS 需要 macOS/Xcode，HarmonyOS HAR 需要匹配 API 22 的 DevEco SDK、ohpm 与 hvigorw。先配置 `ANDROID_HOME` 和 HarmonyOS 工具链路径，命令从仓库根目录运行；以下是维护者检查命令，不是第三方安装步骤。

```sh
bash scripts/verify.sh
# Kuikly 传输替身驱动生产 MediaModule，验证迟恢复 dispose 和图片数量上限。
bash gradlew -p verification-kuikly test
bash scripts/verify-ios-picker.sh
bash gradlew -p verification-consumer compileDebugKotlinAndroid compileKotlinIosArm64 compileKotlinIosX64 linkDebugFrameworkIosSimulatorArm64 compileKotlinOhosArm64
```

启动一个 iOS Simulator 后运行 Picker 检查；多个设备时使用 `MEDIA_SIMULATOR` 指定设备。脚本独立编译 Swift module/消费应用并运行 UIKit 回归，不需要 Gradle。

HarmonyOS HAR 在 `ohos/` 内执行：

```sh
ohpm install --all
hvigorw --mode module -p module=MediaNative@default -p product=default assembleHar --no-daemon
```

需要 SDK 的检查只在对应环境执行；不默认 `clean` 或全仓库构建。独立消费者使用 README 的远程 Maven 坐标，不使用 `mavenLocal` 或源码 `project/includeBuild` 替换。

## Maven 产物维护

Maven Android/iOS/OHOS（按本库实际 target）产物在 macOS 生成并放入版本化 Release 归档；JitPack 下载对应不可变标签的归档，校验 SHA-256 后安装。源码检查不能替代完整 KMP `.module` 与每个引用产物的检查；本地 Maven 验证不能替代默认远程消费。标签、归档与校验和不得覆盖，Maven 二进制不提交到源码仓库。

完整发布步骤与不可变产物约束见 [GY CrossKit 发布流程](https://github.com/gycrosskit/.github/blob/main/docs/发布流程.md)，历史版本见 [发行页](https://github.com/gycrosskit/media/releases)。

## HAR 0.1.3 发布前源码复核

HAR 的拍照/保存临时文件改用实例 UUID 加请求序号；同 cacheDir 的不同页面在同毫秒启动也不会覆盖或删除对方临时文件。目录和本次请求的 finally 清理保持。`node --test ohos/media/test/media.test.cjs` 使用固定时间验证双实例不同路径。全审清单、命令结果在 `build/remote-library-review/coverage.json`。本节源码已随 HAR 0.1.3 prerelease 发布，旧 0.1.2 HAR/hash 的验证只对应旧字节。
