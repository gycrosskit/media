## Gradle 与工具链

根 README 列出远程安装坐标。本库 KMP 产物使用 Kotlin `2.2.21-1.0.0`；OHOS target 必须使用兼容的厂商工具链。项目构建使用 Gradle `8.11.1`、AGP `8.10.1`、Android compileSdk `36`，Gradle 运行使用 JDK 17。源码的 Java/JVM 编译目标与运行 Gradle 的 JDK 是不同要求。

历史 `0.1.4` 阶段：Maven 预发行 `0.1.4` 已发布，Release 与 JitPack 制品审计通过；配套 Swift Package `0.1.2`、HAR `0.1.3` 保持。独立消费者与设备验收状态见 [0.1.4 远程发布验收](0.1.4远程发布验收.md)。

在 `settings.gradle.kts` 中为 Kotlin 插件与依赖分别配置仓库；保留宿主已有仓库：

```kotlin
pluginManagement {
    repositories {
        maven("https://maven.eazytec-cloud.com/nexus/repository/maven-public/")
        google()
        mavenCentral()
        gradlePluginPortal()
    }
}
dependencyResolutionManagement {
    repositories {
        exclusiveContent {
            forRepository {
                maven("https://mirrors.tencent.com/nexus/repository/maven-tencent/")
            }
            filter { includeGroup("com.tencent.kuikly-open") }
        }
        maven("https://jitpack.io")
        maven("https://maven.eazytec-cloud.com/nexus/repository/maven-public/")
        google()
        mavenCentral()
        maven("https://mirrors.tencent.com/nexus/repository/maven-public/")
        maven("https://mirrors.tencent.com/nexus/repository/maven-tencent/")
    }
}
```

上述 exclusive 规则只将 Kuikly group 路由到腾讯 Maven，不改插件仓库或其他 SDK 的仓库规则。Gradle 先选定含 metadata 的仓库后，AAR 缺失不会自动向后切源；该仓库路由的历史实际响应见 [0.1.4 远程发布验收](0.1.4远程发布验收.md)。

Kuikly 模块使用 `2.28.0-2.0.21-ohos`。Swift Package、OHPM HAR 和 Maven KLIB/AAR 分别安装，Maven 不替代原生依赖或宿主桥接。HarmonyOS 包的 `targetSdkVersion` 和 `compatibleSdkVersion` 均为 `6.0.2(22)`，不据接口 API 级别推断当前 HAR 可运行于更低系统。

## Android

`AndroidImagePickerPlatform(activity, permission)` 和 `AndroidImageSavePlatform(activity, permission)` 的 `permission` 是宿主提供的 `suspend (String) -> MediaPermissionState`，返回 `GRANTED / DENIED / BLOCKED / RESTRICTED`。按实际系统授权事实映射，不能把新拒绝一律写成永久阻止。

声明 `CAMERA`；保存相册在 API 28 及以下还需 `WRITE_EXTERNAL_STORAGE`，声明 `maxSdkVersion="28"`。系统 Photo Picker / ACTION_GET_CONTENT 不申请整库读取权限。`pick()`、`save()` 和 `dispose()` 可从消费线程进入，组件在 Main 操作权限与 Picker 状态；宿主销毁时及时 dispose。释放会撤销已回调但尚未交付的旧结果，释放为终态，同一 Picker 实例不能重新使用，后续 pick 返回 Failed；新的页面创建新实例。

AAR 自动合并 FileProvider `${applicationId}.gycrosskit.media`，只暴露应用私有 Pictures 目录。默认 authority 与构造函数匹配，若修改需同步 Manifest。压缩前采样解码并应用 EXIF 旋转/镜像；拍照临时文件结束或取消后清理。MediaStore 写入失败会删除未完成条目。

## iOS 原生

按 README 安装 Swift Package `GycMedia`。调用 `MediaClient.shared.pickImages`，来源 `0` 为相机、`1` 为相册，`maxDimension=0` 禁用压缩：

```swift
import GycMedia

// callback 是宿主实现的 MediaPickerCallback 实例，接收逐张图片和终态。
MediaClient.shared.pickImages(source: 1, maxCount: 3,
                              maxDimension: 2048, jpegQuality: 85,
                              callback: callback)
// saveCallback 实现 MediaSaveCallback。
MediaClient.shared.saveImage(data: imageData, fileNamePrefix: "photo", callback: saveCallback)
// 所属宿主销毁或明确取消时：
MediaClient.shared.cancelImagePicker()
```

`MediaPickerCallback` 实现 `onImage(data:fileName:contentType:)`、`onCompleted()`、`onCancelled()`、`onPermissionDenied()`、`onPermissionBlocked()`、`onPermissionRestricted()`、`onFailed(message:)`。`MediaSaveCallback` 实现 `onSaved()`、三个权限方法、`onInvalidContent()`、`onFailed(message:)`。取消、刚拒绝、已阻止和设备策略限制是不同结果，由宿主分别处理。

Info.plist 配置 `NSCameraUsageDescription` 和 `NSPhotoLibraryAddUsageDescription`；PHPicker 无需整库读取权限，保存只请求 `.addOnly`。无压缩选图保留原始编码；系统相机只给 UIImage 时编码为质量 1 JPEG。

默认从 foregroundActive 场景的 key window 递归查找 presented、Navigation、Tab、Split 和可见自定义 child。多个前台窗口或无法判断的自定义容器，在主线程设置：

```swift
MediaClient.shared.presenterResolver = { [weak page] in page }
```

返回 nil 时本次选择失败。保持同一个 `MediaClient.shared` 的请求所有权。隐藏或不在 window 的 presenter 会失败；展示/关闭转场结束后下一轮主队列重新解析。未展示的 UIViewController 取消立即完成；已经排队展示的 PHPicker 要先完成展示再关闭。连续替换只保留最新请求，旧关闭完成和迟到 delegate 不得关闭新 Picker。

## HarmonyOS Kuikly

HAR 导出的是 `MediaModule`，并非独立 picker/saver 的 ArkTS facade：

```typescript
import { MediaModule } from '@gycrosskit/media';
modules.set(MediaModule.MODULE_NAME, () => new MediaModule());
```

`modules` 是宿主 Kuikly render 的模块注册表，名称为 `GycMedia`。Kotlin Pager 注册 `io.github.gycrosskit.media.kuikly.MediaModule.NAME` 和 Module 实例，该实例实现 `ImagePickerPlatform` / `ImageSavePlatform`。页面结束时 `dispose()`，不复用销毁实例。

相册使用 PhotoViewPicker；保存使用逐次授权对话框，宿主保留系统相机要求的实际权限声明。
0.1.2 的 Kotlin Module/HAR 需成对更新；名称和 pick/save 参数保持，桥内部附加 requestId，新增 cancel(requestId)。
每页模块和其协程取消均在 Kuikly 上下文执行。回调已 resume、协程尚未恢复时发生 dispose，
恢复后仍以 CancellationException 结束；selected 数组先检查数量在 1..request.maxCount，再分配和解码。取消/finally 与 dispose 只取消所属请求，移除回调、结束原生
Promise 等待并拦截后续读写；原生仍由 finally 在当前系统操作返回后释放所属文件/图像/相册 helper。
系统 Picker 由用户关闭，期间原生新 pick 返回 busy，Kotlin 映射为明确的 Failed，不能假称系统页已经关闭。旧 ID 的 cancel 不能取消新请求。

单次输入原图总量、输出结果总量分别不超过 32 MiB。Kotlin 接收图片和 HAR 保存均在 Base64 decode 前检查限额；
原生读取每张图片前检查输入剩余额度，压缩输出检查独立的输出合计后再编码。无压缩保留字节、文件名和 MIME；显式压缩才 JPEG，三类权限结果保持。
更大照片需另行设计二进制传输，不通过增加 Base64 上限规避内存边界。
